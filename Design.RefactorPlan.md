# AttributedDI Refactor Plan (No Modules, Attribute-Only Export)

## Goals

- Remove `IServiceModule` and all module-based registration APIs.
- Generate only service-collection extension methods with direct registrations.
- Generate a single `AddAttributedDi` that calls exported extension methods.
- Discover exported extension methods by scanning assembly-level attributes only.
- Replace `GeneratedModuleNameAttribute` with a new attribute that matches the new semantics.

## New/Updated Public API

- New assembly-level naming attribute (replaces old `GeneratedModuleNameAttribute`):
  - `ServiceCollectionExtensionAttribute(string? extensionClassName = null, string? methodName = null, string? extensionNamespace = null)`
  - Defined in the library project (public, XML-documented).
- Generated export attribute (assembly-level):
  - `ExportsServiceCollectionExtensionAttribute(Type extensionType, string methodName)`
  - Generated by the source generator and applied multiple times at assembly level.
- Generated extension methods per assembly:
  - `public static IServiceCollection Add<AssemblyName>(this IServiceCollection services)`
- Generated aggregator:
  - `public static IServiceCollection AddAttributedDi(this IServiceCollection services)`

## Removed Public API

- `IServiceModule`
- `AttributedDiServiceCollectionExtensions` (AddModule / AddModules)
- `AttributedDiOptions` and the `AddAttributedDi(Action<...>)` overload
- `GeneratedModuleNameAttribute`

## Generator Changes

### 1) Post-initialization attributes

Add embedded source for:

- `ExportsServiceCollectionExtensionAttribute`

Location:

- `src/AttributedDI.SourceGenerator/GeneratedAttributesInitializer.cs`

### 2) Naming collector + resolver

Replace module naming with extension naming:

- New collector for `ServiceCollectionExtensionAttribute`.
  - Parameters customize behavior:
    - `extensionClassName` may be a simple class name or a fully qualified name (e.g. `My.Namespace.MyClass`).
    - If a fully qualified `extensionClassName` and `extensionNamespace` are both provided, implementation may favor whichever is easier; add a TODO to introduce an analyzer later to warn about ambiguous input (analyzer is out of scope for this plan).
    - `methodName` fully replaces the default (no prefixing). Default remains `Add<AssemblyName>`.
- Resolver defaults:
  - Extension class name: `<AssemblyName>ServiceCollectionExtensions`
  - Method name: `Add<AssemblyName>`
  - Namespace: `<AssemblyName>`

Locations:

- `src/AttributedDI.SourceGenerator/ServiceModulesGeneration/ServiceCollectionExtensionNameCollector.cs` (rename / rework)
- `src/AttributedDI.SourceGenerator/ServiceModulesGeneration/ServiceCollectionExtensionNameResolver.cs` (rename / rework)
- `src/AttributedDI.SourceGenerator/KnownAttributes.cs` (replace old attribute name)

### 3) Extension method generation

Stop emitting module class. Generate extension method with direct registrations:

- Replace `EmitRegistrationModule` with `EmitRegistrationExtensions` (single file).
- The generated extension method should:
  - `ArgumentNullException.ThrowIfNull(services);`
  - Emit registration calls directly.
  - `return services;`

Locations:

- `src/AttributedDI.SourceGenerator/ServiceModulesGeneration/ServiceCollectionExtensionCodeEmitter.cs`

### 4) Export attribute emission

Emit assembly-level exports **only when** extension method is generated:

- `[assembly: ExportsServiceCollectionExtensionAttribute(typeof(global::<ExtNamespace>.<ExtClass>), "<MethodName>")]`

Location:

- `src/AttributedDI.SourceGenerator/ServiceModulesGeneration/GeneratedModuleCodeEmitter.cs`

### 5) AddAttributedDi generation (attribute-only scan)

Replace reference scan by type with attribute scan:

- Collect exports from `compilation.Assembly.GetAttributes()` + referenced `IAssemblySymbol.GetAttributes()`.
- Order deterministically by fully qualified extension type + method name.
- Emit `AddAttributedDi` that calls each export:
  - `global::<ExtensionType>.<Method>(services);`

Locations:

- `src/AttributedDI.SourceGenerator/ServiceCollectionExtensionsGeneration/ExportedServiceCollectionExtensionCollector.cs` (replace)
- `src/AttributedDI.SourceGenerator/ServiceCollectionExtensionsGeneration/AttributedDiServiceCollectionExtensionsPipeline.cs`
- `src/AttributedDI.SourceGenerator/ServiceCollectionExtensionsGeneration/AttributedDiServiceCollectionExtensionsEmitter.cs`

## Testing / Validation

- Defer testing and test refactoring until after implementation is complete and reviewed.

## Open Implementation Notes

- Keep `ExportsServiceCollectionExtensionAttribute` `internal` in generated source; it exists solely for generator-to-generator communication.
- Add `ServiceCollectionExtensionAttribute` to the library project (public, XML doc required).
- Ensure new attribute names are in `KnownAttributes`.
- No code paths should rely on `IServiceModule` or module types after this change.
